# access-hub — build plan (v1)

> **Parallel scope.** You own **access-hub only**. Do not edit
> [access-guard](https://github.com/Aakvatech-Limited/access-guard). The wire contract is frozen in
> [`docs/PROTOCOL.md`](PROTOCOL.md) (this repo is authoritative for it) and the shared code in
> [`access_hub/protocol.py`](../access_hub/protocol.py) — implement against them; do not change
> them without a coordinated change to the guard's identical copy. Full design rationale is in
> [`docs/DESIGN.md`](DESIGN.md); background in [`docs/CONTEXT.md`](CONTEXT.md).

The hub runs on the helpdesk site, which is **not** attacker-controlled, so DocTypes are fine here.

## Conventions
- Whitelisted methods live in `access_hub/access_hub/api.py` → callable as `access_hub.api.<fn>`.
- Import shared constants/errors from `access_hub.protocol`.
- Secrets via `frappe.conf` only, never DocType fields.

## Tasks (in order)

1. **Keypair command.** A `frappe.commands` CLI command (`bench access-hub-generate-keypair`) that
   generates an Ed25519 PASETO keypair (`pyseto`/`paserk`), writes `access_hub_private_key` **and**
   `access_hub_public_key` (see `protocol.CONF_HUB_PUBLIC_KEY_LOCAL`) to `site_config.json`, and
   prints the `k4.public...` key. **The public key is persisted on the hub itself, not just printed
   once** — it's needed later for the enrollment-help surface below. Idempotent guard: refuse to
   overwrite an existing key unless `--force`. A companion command
   (`bench access-hub-enroll-info`) re-prints the hub URL + public key on demand. Both commands
   already exist in `access_hub/commands/__init__.py` — extend, don't duplicate.

2. **Remote Site DocType.** Fields per PROTOCOL §1–2: `host` (title), `port` (Int, default 443),
   `protocol` (Select https/http, default https; on port change suggest http only for `:80` /
   `*.localhost`, never auto-downgrade), autogenerated `name`, `enrollment_type` (Select
   manual/fc), `transport_token` (Data, admin-input or autogenerated ≥8 chars — validate length),
   `transport_token_hash` (read-only, set from `protocol.transport_token_hash` on validate; the
   plaintext field is cleared after hashing / shown once). `announce` upserts a row.
   **Add a "Get Enrollment Info" button/action** on the Remote Site form (whitelisted method,
   e.g. `access_hub.api.get_enrollment_info(remote_site)`) that returns/displays the full
   three-value snippet a client admin needs to enroll: `access_guard_hub_url` (=
   `frappe.utils.get_url()`), `access_guard_hub_public_key` (= `frappe.conf.get(CONF_HUB_PUBLIC_KEY_LOCAL)`,
   error clearly if no keypair generated yet), `access_guard_transport_token` (the plaintext token —
   only available at creation/regeneration time, since only the hash is stored after that; show a
   clear message if it's already been rotated away). This is the "help" surface the user asked for
   when enrolling a new site — it must not require reading site_config.json by hand.

3. **Access Hub Settings (Single).** All `POLICY_*` fields from `protocol.POLICY_DEFAULTS`
   (deny/warn rule child table → serialized to the normalized `rules` list; `session_expiry`,
   always-log doctypes, max key size, `log_reads`, notice text, sync toggle, retention, push grace,
   name suffix).
   On save: build the policy object, sign it as a PASETO `v4.public` **policy token**, and
   best-effort push to reachable guards (`receive_policy`); failures are swallowed.

4. **Access Grant DocType + Request-access UI + minting.** `Access Grant`: employee, Remote Site,
   `jti`, status (Issued/Expired), timestamps (no approval workflow in v1). A desk page/button lists
   Remote Sites → creates an Access Grant → mints the grant token (PROTOCOL §3, `aud` =
   `transport_token_hash`, `exp` = iat + `GRANT_TTL_SECONDS_DEFAULT`) → redirects the browser to the
   guard accept URL.

5. **Ingest endpoints** (PROTOCOL §5). `api.py`: `get_policy`, `push_logs`, `announce`,
   `report_provisioning`. Shared decorator (`ingest_endpoint`) that authenticates the transport
   token — sent as `X-Access-Guard-Transport-Token`, **not** `Authorization` (see PROTOCOL §5 /
   `protocol.py::TRANSPORT_TOKEN_HEADER` for why: a custom header means Frappe's own
   `validate_auth()` never intercepts the request, so no `auth_hooks` registration is needed —
   `ingest_endpoint` is the only place this token is ever checked) — by hash match
   (→ `TransportAuthError`) and enforces `check_pv`. Errors returned via
   `AccessProtocolError.as_response()` + `frappe.local.response.http_status_code`.

6. **Hub-side log storage.** `Session Log` DocType (one row/session: Remote Site, jti, employee,
   start, end, logout reason). `push_logs` appends ndjson to files at `base/<host>/<jti>.jsonl` and
   maintains a lightweight index DocType (host, jti, employee, date, path, size, lines). **Safe
   serving:** a method that serves a log by index-row id → resolves a canonical path → asserts it is
   inside `base_dir` (traversal guard) → supports line/byte ranges. Hub System Managers only.

7. **hooks.py wiring.** Register the Request-access page and any `website_route`/desk entries.

## Tests (`bench run-tests`)
Put tests under `access_hub/access_hub/tests/` (add `__init__.py`) or as `test_*.py` next to each
DocType. Use `FrappeTestCase`. Cover:
- keypair gen → mint token → verify with the public key → claims match; `aud == transport_token_hash`.
- policy token signs + round-trips; `POLICY_DEFAULTS` seed present.
- ingest auth: correct token hash passes, wrong token → `TransportAuthError`; `pv` mismatch → 426.
- log serving: valid id serves; `../` / absolute path attempts are rejected by the traversal guard.
- Remote Site: `transport_token_hash` set on validate; sub-8-char token rejected.

**Run:** `bench --site <hub-site> run-tests --app access_hub` (site needs developer mode + the app
installed; `pip install pyseto` in the bench env first). See HANDOVER.md for site setup.

## Done criteria
`bench --site <hub-site> run-tests --app access_hub` is green; a minted token verifies against the
printed public key; `get_policy` returns a token a fresh keypair-holder can verify.
